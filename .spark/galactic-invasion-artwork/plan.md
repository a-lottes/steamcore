## 1. Architecture Decision

- **Context:** The sheet is a concept illustration (gradients, brown panel fill, vignette, glow halo), so the tool does art *reduction*, not import (§8). Its format is **confirmed, not assumed**: `1536×1024`, bit depth 8, colour type 6 (RGBA), compression 0, filter 0, **interlace 0** (IHDR read 2026-09-16). Pillow is not installed, and `tools/check_constraints.sh:904` already enforces a **stdlib-import allowlist** on `tools/*.py` — "no pip install, no Pillow" is a shipped, automated project rule, not an open question. `fb_view.py` already hand-builds PNGs with `zlib`+`struct` and holds the canonical `PALETTE`. The firmware side already has a compile-time-validated `' '`/`'#'` row-string art convention (`galactic_invasion_art.h`, `font.cpp`) with the ESP-IDF scars (`std::abort()` not `throw`; explicit `<cstddef>`) already paid for. Eleven test files locate entities by palette colour; four of them assume "any `DARK_ORANGE` pixel is an enemy shot", and two of those use it to *drive* a round, not merely to assert.
- **Decision:** Six locked choices.
  1. **No new dependency.** The generator decodes PNG with `zlib`+`struct`: colour type 6 (and 2, for the synthetic test fixtures `fb_view.encode_png` writes), bit depth 8, non-interlaced — no Adam7, no bit-depth normalisation, no palette resolution, but the per-scanline filter path (types 0–4) is mandatory. Anything outside that subset is a named non-zero failure, never a best-effort guess. `PALETTE` is imported from `fb_view` — the one Python-side palette, already cross-checked against the C++ by `tools/test_roundtrip.py`. Only `hashlib` joins the allowlist.
  2. **Output format = the existing art convention, widened to four symbols.** The generator emits `' '`=BLACK, `'.'`=DARK_ORANGE, `'+'`=ORANGE, `'#'`=BRIGHT_ORANGE row strings plus a `constexpr` converter and the same `rowIsExactWidth`/`std::abort()` validator — **not** a `Color[]` literal dump. Diffable, reviewable, compile-time-validated, and identical in shape to what a human would hand-author (AC-3.11's two routes differ only by banner).
  3. **Background rule (D1) = alpha gate, then border-seeded chroma flood + halo closure**, all integer arithmetic, applied before fit and quantisation, in this fixed order. **(a) Alpha gate, primary:** `a < alphaMin` → BLACK. **(b)** `B` := per-channel median of the crop's 1-px border ring **over alpha-surviving pixels only**; if the whole border was alpha-gated away, (b)–(d) are skipped and the banner records `background: alpha`. Otherwise abort non-zero if >25 % of the surviving border pixels lie further than `bgTol` from `B` (the crop's border must be background). **(c)** 4-connected BFS from every border pixel, accepting iff `dist²(p,B) ≤ bgTol²` → BLACK. Seeded from a global reference, so the result is order-**independent**, not merely order-fixed. **(d) Halo closure:** repeat until fixpoint — a surviving pixel with `dist²(p,B) ≤ haloTol²` that is 8-adjacent to a BLACK-mapped pixel also becomes BLACK. Two thresholds (`bgTol` hard, `haloTol` soft-but-contiguous) kill the glow ring without eating interior dark pixels, which are unreachable from the border. **This one rule covers both worlds the alpha channel can turn out to be** (see T2): if the sheet's background is transparent, (a) does the work and (c)/(d) clean up halo remnants; if it is opaque — which the visible brown panel fill suggests — (a) is a no-op and the rule is exactly the chroma flood as designed. Which of the two actually happened is measured once, recorded in the banner, and never guessed.
  4. **Fit (D2) = integer box mapping + coverage rule.** Target cell (i,j) covers source x∈[⌊i·W/w⌋,⌊(i+1)·W/w⌋) (same for y). A cell is BLACK iff `nonBg·100 < coverageMin·total`; otherwise **every non-background source pixel in the cell is quantised individually and the cell takes the majority-vote palette index, ties breaking to the lowest `Color` enumerator** (T9 deviation, user-approved 2026-09-16: an original "integer mean of non-background pixels, then quantise" order produced isolated-pixel artifacts on this sheet's anti-aliased art at a large downscale factor — see plan §Deviations for the full sweep writeup). Sprites fill their frozen box (anisotropic); the logo preserves aspect at `height = 7·kGlyphHeight`.
  5. **Quantisation (AC-3.8) = nearest palette entry by squared Euclidean RGB distance on integers; ties break to the lowest `Color` enumerator** (BLACK < DARK_ORANGE < ORANGE < BRIGHT_ORANGE). Total, float-free, documented in the banner.
  6. **Locators migrate first, on unchanged art** (PO recommendation, adopted — see §3 T1), and migrate to **sprite-template matching against the `Sprite` constant itself**, not to a different colour. A locator written against `kEnemyShotPixels` follows every future art change for free; a locator written against an ink breaks on the next one.
- **Alternatives considered:**
  | Alternative | Why rejected |
  |---|---|
  | Pillow as a dev-only dependency | `check_constraints.sh`'s allowlist fails the build on it; `fb_view.py` proves stdlib PNG handling is ~60 lines here — and with interlace, sub-8-bit depths and palettes all ruled out by the measured IHDR, the remaining surface is a filter loop. A liability with a shipped lint rule against it beats "we write those 60 lines". |
  | Emit `Color` array literals / a binary blob | 8 904 unreviewable entries; a blob re-opens "the build reads an asset". Row strings keep `/peer-review` able to *see* the art in the diff. |
  | Trust the alpha channel as the whole background rule | Cheaper, but only if the background is actually transparent — the visible brown panel argues it is not, and a rule that silently degrades to "keep everything" is precisely D1's failure. Alpha is kept as the *first, primary* gate, never as the only one. |
  | Global luma/alpha threshold for the background (D1) | The panel fill is *brighter* than the sprites' own dark outline, so no global threshold separates them; it would erase interior shading and keep the halo. |
  | Local-tolerance ("magic wand") flood | Acceptance would depend on visit order → AC-3.3 would hold only by fixing the queue, never by construction. |
  | Nearest colour in CIELAB / perceptual metric | Needs floats (cross-platform determinism risk) and buys nothing across four inks on one hue ramp. |
  | Hand-transcribe the logo, no tool | Settles nothing for the next sheet and forfeits US-3 entirely; the sheet's wordmark is ~9 000 cells. |
  | Migrate locators together with the new art | The two round-driving tests (`round_test.cpp:219`, `dump_test.cpp:133`) *steer* the player by that detector: one failure mode would read as the other. Cost of separating: one task. |
  | Provenance check as a host test | The harness has no warn state — it would fail the gate, which A13 forbids and AC-3.2 (build green without `assets/`) makes impossible. |
- **Consequences:** Easier — a second sheet costs a region-table entry; the art lives in the diff; ink changes no longer break tests. Harder — we own a small PNG decoder (bounded by a loud, tested failure taxonomy); the background rule has five tuned parameters plus one measured alpha finding that must be recorded per artefact; two build systems must both learn the new `.cpp` (`firmware/system/main/CMakeLists.txt` is explicit by design).

## 4. Test Strategy

- **Host unit tests (`make test`, the real gate) — every Must story.** US-1: `galactic_invasion_logo_test.cpp` covers the bounds derivation, the twice-proven disjointness (header `static_assert` + independent runtime helper), the `kTitlePromptBounds` identity, the all-other-pixels-BLACK claim, the START edge and the held-at-boot case, plus replay byte-equality. US-2: `galactic_invasion_art_test.cpp` carries the AC-2.10 (i)–(iv) structural set, the two-background transparency proof and the footprint `static_assert`s; the eleven existing behavioural files are the regression oracle and must pass **textually unchanged** (AC-2.2). US-3: `tools/test_generate_sprite_data.py` under `make test-python` covers the decoder, all five abort paths, both background paths (alpha-transparent and opaque) on synthetic images, the anisotropic fit, the tie-break and the byte-identical re-run.
- **Integration-ish host gates.** `make test-asan` proves AC-1.10 (inherited `blit` clipping, not re-implemented); `make test-gcc` and `make lint` prove NFR-4's second compiler and every structural rule; the `assets/`-moved-aside run (T12) is the only real proof of AC-3.2.
- **Device build (`idf.py build`), not hardware.** AC-3.7/NFR-4: run at T6 the moment the first generated header exists — deliberately *before* the rest of the art, because `text-rendering`'s scar cost two features of latency — and again at T10.
- **Deliberately not automated.** AC-1.7, AC-2.4, AC-2.5, AC-2.7 are design judgements and go to `/look-and-feel` on the 1:1 dump from T13 — a pixel test cannot decide legibility, and predicting it from the sheet is exactly what D7 forbids. AC-4.1/4.2 need a human at the cabinet (`/demo-day`); AC-3.9's warning-to-finding step is a `/peer-review` duty by A13's own design.

## 5. Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|

## Deviations

- **T1 — the locator needed two properties the task description did not
  name**, both discovered by tests failing rather than by reading. (i)
  *Clipping*: `stepEnemyShots` retires a shot only once `y >=
  Framebuffer::height()`, so a shot at `y = height - 1` is on screen with
  five of six rows off the bottom, and `galactic_invasion_enemy_fire_test`
  deliberately hunts for exactly that shot. A whole-window comparison
  finds nothing there. (ii) *BLACK-as-transparent*: `blit` never writes a
  sprite's BLACK cells, so a shot overlapping the player shows the ship
  through its gaps — and one test asserts precisely that overlap. A strict
  cell-for-cell match would have lost the shot exactly where it is being
  looked for. Both are implemented as documented properties of
  `findEnemyShots` with their own negative controls; a top-anchor rule
  keeps clipping from counting one outgoing shot several times.
