## 1. Architecture Decision

- **Context:** Every product question is settled (A1–A15, C1–C17). What is left is genuinely technical and the spec
  says so explicitly: where a *game* (not an engine primitive) lives in this tree, how richer per-entity state maps
  onto the deliberately-minimal `Entity`, how win-vs-loss is tracked without touching `GameState`, the exact pixel
  arithmetic behind a 3×6 formation on 240×160, and the concrete tick constants that make all of it deterministic.
  Nine shipped primitives compose for the first time in one file; the integration risk is the whole feature.

- **Decision:**

  1. **The game lives under `games/`, not `include/steamcore/`.** `games/galactic_invasion/galactic_invasion.{h,cpp}`
     plus `galactic_invasion_art.h`, `namespace steamcore::games`, snake_case files. Constitution §5 already commits
     to this layout ("each game is one self-contained directory under `games/`") and README's Phase 3 names four
     games; putting the first one in the engine's public header tree would make `include/steamcore/` mean two
     different things and would hand game code the engine's include path by default. Cost, paid once here for every
     future game: `Makefile` gains `GAME_SRCS := $(wildcard games/*/*.cpp)` and `-Igames` (include spelling
     `"galactic_invasion/galactic_invasion.h"`), and `games/` is invisible to every existing `check_constraints.sh`
     rule until T14 extends them (R4 — the single most valuable thing the lint task does).
     **Deviation, stated:** the game's *tests* join the one existing host suite in `firmware/steamcore/test/`
     rather than living under `games/galactic_invasion/test/`. A second test root would need either a second
     include path into `test/` (weakening the Makefile's "exactly one include path" claim) or `../../../` includes
     of `test_harness.h`, for no gain — the harness, `FILTER`, ASan and bench targets are all built around one
     suite. Source self-containment, which is what §5 is about, is unaffected.
  2. **Public surface is exactly `GalacticInvasion{}` + `update(const GameInput&)` + `render(Framebuffer&)`** —
     no state accessors at all (NFR-5). Everything a test needs to assert is a player-observable pixel, so tests
     assert against independently-constructed expected framebuffers (the `title_screen_test.cpp` pattern) via a
     shared `galactic_invasion_fixture.h`. The header additionally exports its *layout constants* as `constexpr`
     data — the `title_screen.h` precedent — so no test restates a coordinate the header already computed.
  3. **Layout rectangles are `steamcore::Entity`, and disjointness is `static_assert(!overlaps(a, b))`.**
     `Entity` is already x/y/w/h, and `overlaps` is already `constexpr`, already tested and already the general
     four-way separating-axis test CLAUDE.md asks for — writing a bespoke `Rect` plus a hand-rolled axis expression
     would be a second, drifting copy of both. The runtime half of the same proof (CLAUDE.md: prove it twice) uses
     its own independent intersection helper in the test file, never `overlaps`.
  4. **Collision: separate typed pools, `checkCollision` per meaningful pair — no mixed-pool `sweepCollisions`.**
     Three explicit rules per tick: player-shot × 18 enemies, player × 18 enemies, ≤3 enemy shots × player = ≤39
     pair tests. A single sweep over one mixed ~25-entity array is ~300 pairs, of which enemy×enemy and
     enemy×enemy-shot are meaningless, and it would force a `kind` tag into the pool plus a discriminating callback
     — inventing the identity mechanism `Entity`'s minimality (collision-system A1/R4) deliberately refuses. Typed
     pools need no tag, waste no pairs, and put each rule's resolution where it belongs. AC-4.1 permits either
     ("`checkCollision`/`sweepCollisions`"). **Recorded for `/peer-review`:** spec NFR-1's parenthetical says
     "~25-entity collision sweep via `sweepCollisions`" — that is descriptive of expected cost, not an AC; the
     benchmark (T15) measures the real full tick, so the NFR's measurable claim is unaffected (R6).
  5. **A destroyed enemy is a zero-size `Entity`, and that is the only aliveness bit.** `struct Enemy { Entity body; };`
     in a fixed `Enemy enemies_[kEnemyCount]` (18); destruction sets `body.w = body.h = 0`, which
     `collision.h` already defines as "overlaps nothing" — so a dead enemy is structurally unhittable rather than
     conditionally skipped, and `isAlive(e)` is `e.body.w > 0`, one source of truth (a parallel `bool alive` could
     drift from it). Rendering and the survivor bounds skip `w <= 0`. Positions are **derived**, never accumulated:
     `body.x = kFormationStartX + col * kEnemyPitchX + offsetX_`, same for y — so a dead enemy's grid slot stays
     coherent and a restart is a plain re-initialisation, no dynamic sizing anywhere (NFR-2).
  6. **Geometry (all derived from `config.h`/`font.h`, no bare `240`/`160`/`16`/`8` anywhere).** Sprites:
     player `12×12`, enemy `12×10`, projectile `2×6` (one projectile sprite serves both directions, §6's "one
     projectile type"). Formation: `kEnemyGapX = 12` → `kEnemyPitchX = 24`; `kEnemyGapY = 6` → `kEnemyPitchY = 16`
     (computed, never spelled); width `5*24 + 12 = 132`; `kFormationStartX = (Framebuffer::width() - 132) / 2 = 54`,
     leaving 108px of horizontal travel; `kFormationStartY = 2 * kGlyphHeight = 16` (HUD row 0, one empty glyph row
     — §8 finding 4's spacing recommendation, adopted). Rows occupy y ∈ [16,26)/[32,42)/[48,58).
     Player: `kPlayerY = Framebuffer::height() - kPlayerHeight - 4 = 144`, `kPlayerStartX = (240-12)/2 = 114`.
     HUD: `SCORE: nnnn` (11 glyphs, 88px, zero-padded so its bounds are constant) at (0,0); `LIVES: n` (8 glyphs,
     64px) at `(Framebuffer::width() - 8*kGlyphAdvance, 0) = (176,0)`; 88px of clear gap between them (§8 finding 4).
     Threshold `kFormationThresholdY = kPlayerY`: fires when any survivor's `y + kEnemyHeight >= 144`, i.e. after 11
     descents (58 + 8k ≥ 144).
  7. **Timing is tick-counted, all constants named (A11/NFR-3).** Player `2 px/tick`; player shot `4 px/tick` up;
     formation `kFormationStepX = 4` every `kFormationStepTicks = 18` ticks; on a step that would push any survivor's
     rect outside `[0, Framebuffer::width())`, no horizontal move happens — the direction flips and every enemy
     descends `kFormationDescendY = kEnemyPitchY / 2 = 8` **once** (AC-3.3). Order inside `update`: (1) tick counters,
     (2) player move, (3) shots move + off-screen removal, (4) formation step, (5) collisions, (6) win check,
     (7) threshold check, (8) end-of-tick invulnerability decrement — then `session_.advance(input, sessionEnded)`.
  8. **Win/loss (US-11, the spec's open question) — `enum class Outcome { NONE, WIN, LOSS }`, one private field.**
     `outcome_` is set by the simulation step that *decides* the round is over — win in step (6) when no enemy is
     alive, loss in step (5)'s last-life branch or step (7)'s threshold — and `sessionEnded` is returned from the
     same simulation call, so the flag is always set **strictly before**, and in the same tick as,
     `session_.advance(input, true)`. `render()` reads `outcome_` only under `GAME_OVER`. `resetRound()` clears it to
     `NONE`. `GameState` gains nothing; `game_state.{h,cpp}` are not touched (T17 proves it with `git diff --exit-code`).
     Round boundaries: `update` captures `const GameState before = session_.state()`, simulates only if `before ==
     PLAYING`, calls `advance`, then calls `resetRound()` iff `before != PLAYING && state() == PLAYING` — one place
     that resets formation, offsets, direction, player x, shots, score, lives, invulnerability, RNG seed and
     `outcome_` (A9/AC-6.2/AC-6.3).
  9. **Lives, invulnerability and flicker.** `lives_` starts at 3; a hit with `lives_ > 1` decrements, clears the
     player shot, snaps `player_.x = kPlayerStartX` and sets `invulnTicks_ = kInvulnerabilityTicks (120)` — all in
     the hitting tick, no `sessionEnded`; a hit at `lives_ == 1` sets `LOSS` and `sessionEnded` instead (AC-10.5).
     Exact window: `const bool wasInvulnerable = invulnTicks_ > 0;` is read at the **top** of the tick and is what
     collisions consult; `if (wasInvulnerable) --invulnTicks_;` runs at the **bottom**. So the tick that sets 120
     does not decrement, ticks T+1…T+120 are protected, and T+121 is vulnerable — exactly 120, boundary-testable
     (AC-10.3/10.4). Flicker (AC-10.8): the player sprite is `blit`'d iff
     `invulnTicks_ % kFlickerPeriodTicks < kFlickerHalfPeriodTicks` with `kFlickerHalfPeriodTicks = 4`,
     `kFlickerPeriodTicks = 2 * kFlickerHalfPeriodTicks` — 4 on / 4 off, 120 divides evenly, and `invulnTicks_ == 0`
     falls in the visible half so the vulnerable ship is never accidentally hidden. Formation, shots and HUD draw
     unconditionally.
  10. **Sprite art mirrors `font.cpp` exactly, including its two device-build scars.** `struct SpriteArt { const char*
     rows[H]; }` of `' '`/`'#'` string literals → `constexpr spritePixel()` (row-width check by reading `row[W]`,
     invalid marker → a non-`constexpr` `[[noreturn]] reportInvalidSpriteArt()` that calls `std::abort()`,
     **never `throw`**) → `constexpr buildSprite()` → `inline constexpr std::array<Color, W*H>` → `inline constexpr
     Sprite`. `<cstddef>` and `<cstdlib>` are included explicitly, not relied on transitively (CLAUDE.md: both bugs
     `start-screen` T11 found in exactly this code shape). One on-colour per sprite, not per-pixel shading: player
     `BRIGHT_ORANGE`, enemy `ORANGE`, projectile `BRIGHT_ORANGE`; identity comes from silhouette (AC-12.4,
     constitution §6). Intended art (§8 finding 1: nose-up wedge / blocky top-heavy notched / slim bar):

         player 12×12 (rows 1-12)          enemy 12×10                    projectile 2×6
         "     ##     " "    ####    "     "  ##    ##  " "############"  "##" "##"
         "     ##     " "   ######   "     "   ##  ##   " "############"  "##" "##"
         "    ####    " "  ########  "     "  ########  " "##  ####  ##"  "##" "##"
         "    ####    " " ########## "     " ## #### ## " "##        ##"
         "   ######   " "##  ####  ##"     (rows 5-6 solid, 7-8 notched,
         "   ######   " "##        ##"      9-10 legs: "  ##    ##  " / " ##      ## ")

  11. **Shoulds are ordered last and cut cheaply.** US-8 (T10) then US-9 (T11) — built in that order because spec C6
     cuts US-9 *first*. Both are additive: T8 factors the hit resolution into one `resolvePlayerHit()` that US-8's
     enemy shots merely call, and US-9 replaces the constant `kFormationStepTicks` with
     `stepIntervalTicks(alive) = kStepTicksMin + (alive-1)*(kStepTicksBase-kStepTicksMin)/(kEnemyCount-1)`
     (integer, monotone, deterministic; 18 at 18 alive → 6 at 1). Cutting either leaves T12–T17 covering fewer
     files and nothing to rewrite.

- **Alternatives considered:**
  | Alternative | Why rejected |
  |---|---|
  | Put the game in `include/steamcore/` like every prior feature | Every prior feature *was* engine. Constitution §5 already commits games to `games/`; the first game is where that gets built, or the layout is fiction. `include/steamcore/` would also grant game code the engine's include path |
  | One mixed `Entity` pool + `sweepCollisions` + a kind tag | Needs an identity field `Entity` deliberately lacks (collision-system A1/R4) plus a discriminating callback, and pays ~300 pair tests for ~39 meaningful ones. Rejected on both counts, not on cost alone |
  | `bool alive` on `Enemy` alongside the rect | Two sources of truth for one fact; the zero-size trick is already `collision.h`'s own documented mechanism and makes a dead enemy structurally unhittable |
  | Accumulate `body.x += step` per enemy | 18 accumulators that can drift; derived-from-offset positions make "the formation is a rigid grid" (AC-3.1) structural |
  | Add `WIN` to `GameState`, or a `sessionOutcome` parameter to `advance` | Forbidden outright by A3/NFR-5/§6 — the whole point of US-11's open question was solving it *without* that |
  | Expose `lives()`/`score()`/`state()` accessors for testability | NFR-5 says internal state stays private. Asserting through rendered pixels is both the smaller surface and the stronger claim (it proves the player can actually see it) |
  | A bespoke `Rect` + hand-written separating-axis expression for the HUD bounds | `Entity` + `constexpr overlaps` already is that test, shipped and tested. A second copy is exactly the drift class CLAUDE.md's layout note warns about |
  | Per-pixel two-tone art (`'#'` bright, `'+'` mid) | More validator surface for shading the constitution explicitly de-prioritises ("clear silhouettes", not gradients). One colour per sprite keeps the validator byte-identical in shape to `font.cpp`'s |
  | Import `assets/sprites/galactic_invation.png` (even offline, once) | A14/§6/C15 exclude it; T14 makes "no `assets/`/`.png` reference" a lint rule, mirroring start-screen's own |
  | `snprintf` for `SCORE: %04d` | Pulls `<cstdio>` into game logic for four digits; a fixed `char buf[N]` digit loop is ~10 lines, allocation-free and trivially deterministic |
  | Rising-edge `fire` detection | AC-2.1/2.2 define the constraint as *single active projectile*, not as one-shot-per-press. Edge detection is `GameSession`'s job for `start` only (`game_loop.h`), and inventing a second one is scope |
  | Separate test root `games/galactic_invasion/test/` | Needs a second include path into `test/` or `../../../` includes of the harness, for no gain — see Decision 1's stated deviation |
  | No device task at all (collision-system's precedent) | Applies to a header with no rendering; this feature's `constexpr` art validator is *precisely* the code shape whose `throw`/`<cstddef>` bugs went undetected for two features (CLAUDE.md). One `idf.py build` is cheap insurance |
  | A hardware-gated "human plays a round" task | No AC requires the board, and a blocked task needs a Should story to hang on — there is none. §4 records it as `/demo-day`-deferred instead of inventing an orphan row |

- **Consequences:** *Easier* — 100% of Must ACs are provable with `make test`/`test-asan`/`test-gcc`/`lint`/`bench`;
  the win/loss split needs no engine change; derived positions make restart trivially total; `!overlaps()` gives HUD
  disjointness for free at compile time; typed pools keep collision cost ~39 pairs/tick, far inside NFR-1.
  *Harder* — a second build system (`games/` in `Makefile` **and** `CMakeLists.txt`) can drift (R1); `games/` starts
  outside every lint rule (R4); no accessors means tests must assert through pixels, which is why the fixture header
  (T3) exists; and the game now carries several interacting tick counters whose only real defence is the replay and
  mutation passes (T9/T13).

## 4. Test Strategy

- **Every Must AC is host-verifiable, and that is the whole strategy** (`make test`, `test-asan`, `test-gcc`, `lint`,
  `bench`, `view`). This feature introduces no ESP-IDF dependency, no `port/` file and no peripheral: it composes
  `Framebuffer`/`Sprite`/`blit`/`drawText`/`drawTitleScreen`/`GameSession`/`GameLoop`/`collision.h` only. **T16 is
  therefore a compile-only device task, not a hardware-gated one** — it exists because `collision.h` and the new
  `constexpr` art validator have never been compiled by the ESP-IDF toolchain, and CLAUDE.md records exactly that gap
  biting `start-screen` mid-increment. **No hardware-gated row exists, deliberately:** no AC needs the board, and a
  blocked task would need a Should story to hang on (there is none). The spec's own deferred "a human plays a full
  round on the device" signal stays with `/demo-day`; per constitution §8 QA records it as not capturable, with the
  reason — never as passed, never substituted.
- **US-1/US-2/US-3 (movement, firing, formation)** — T3/T5/T6 are per-tick arithmetic batteries asserted through
  rendered pixels, with both edges of every clamp and both sides of every interval boundary (tick 17 vs 18, the
  last on-screen tick vs the first off-screen one), so an off-by-one cannot hide behind a passing midpoint.
- **US-4/US-5/US-10/US-11 (the round's stakes)** — T7/T8/T9 script whole rounds and assert the frame *and* the tick
  on which each transition takes effect, since AC-5.1/AC-10.5 are same-tick claims that a next-tick implementation
  would otherwise satisfy visually. T13 then mutation-verifies the four rules whose failure would be invisible: the
  single-active-projectile guard, the threshold failsafe (an exploit-closer that is silently *absent* if wrong,
  never obviously broken), the invulnerability window boundary, and the win/loss width margin — each detector shown
  firing, because "no failures" and "nothing looked" are otherwise indistinguishable.
- **US-6 (title → play → restart)** — T1 proves the `READY` composition against a reference frame built only from
  `drawTitleScreen`; T9 proves both restart paths land on a frame byte-identical to a fresh round's.
- **US-7/US-12 (HUD, sprites)** — T4/T2 assert against independently-built expected framebuffers; disjointness is
  proven twice, once at compile time via `!overlaps()` and once at runtime with a helper that shares no code with it.
  AC-12.3 stays a `/peer-review` source read and AC-12.4 a design-review judgement, per the spec — T12 exists so
  both are done against the real rendered PNG at actual scale rather than against the source listing.
- **US-8/US-9 (Shoulds)** — T10/T11, ordered last, US-8 before US-9 because C6 cuts US-9 first. Cutting either leaves
  T12–T17 covering fewer files; the only edits are dropping the corresponding file names from T14's lint set and the
  worst-case shape T15 measures — both named in those rows.
- **NFR-3 determinism** is proven by replay (two fresh instances, 900-tick script, per-tick `framebuffersEqual`) and
  guarded by lint, not by inspection. **NFR-1** is measured and printed by a bench outside the correctness gate,
  never asserted as a wall-clock `CHECK` — the established posture here.
- **Deliberately not automated, with reasons:** browser `/demo-day` (no browser-observable surface, constitution §8);
  real GCC coverage (`/usr/bin/g++` is Apple clang — `make test-gcc` stays honestly reported as nominal); on-device
  play (above); and AC-12.3/AC-12.4, which the spec itself assigns to source reading and design review.
