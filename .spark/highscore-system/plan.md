## 1. Architecture Decision

- **Context:** Every product question is settled (A1–A15, C1–C13). Three technical ones were parked for this
  ceremony (A4 score exposure, A5 storage, A6 slot count), and the Design Review added two layout problems this
  codebase has never had (R2 runtime-variable text width, R3 a 1-to-5-row screen). This is also the first feature
  to write bytes to flash, i.e. the first user of constitution §6's format-version non-negotiable, and the first
  to change a **released** type's public surface (`GalacticInvasion`, AC-5.2/AC-5.3).

- **Decision:**

  1. **A4 — one additive public member: `RoundResult roundResult() const`.** A new 2-field POD
     `steamcore::RoundResult { bool ended; int32_t score; }` in its own tiny header is the engine↔game
     round-end reporting contract any future game implements; `GalacticInvasion::roundResult()` returns
     `{session_.state() == GameState::GAME_OVER, score_}`. One member, one purpose, score only — no lives, no
     formation, no `Outcome`. **`won` is deliberately not in the struct:** nothing consumes it (AC-2.1/F3/C12
     forbid outcome text on the entry screen), and an unused field is speculative surface. `galactic_invasion.h`'s
     own doc comment, which today reads "Public surface is exactly this type's constructor, `update()` and
     `render()` … no accessor for score", is **amended in the same edit** — AC-5.2's "explicitly amended, not
     silently contradicted" lands there and in this plan; `.spark/galactic-invasion/spec.md` is a released
     artifact and stays untouched.
  2. **The flow composes ABOVE the game, not inside it: `HighscoreGame<Game, Store>`** (header-only template,
     `game_loop.h`'s own shape). It holds `Game&`, `Store&`, a slot, a display name and a `HighscoreFlow`, and it
     itself satisfies `GameLoop<Game>`'s concept — so the shipped `GameLoop`, `GameSession`, `GameInput` and
     `Framebuffer` contracts are composed **completely unmodified** (NFR-4). Per tick, exactly one
     `game_.update()` call happens on every path:
     - flow inactive: `game_.update(in)`, then read `roundResult()`; on the *transition* into `ended` (latched by
       one `bool reported_`, AC-5.1's "exactly once"), consult the pure `qualifies(table, score)` and, if it
       passes, `flow_.begin(score)` — **the same tick**, before `render()` runs, so AC-2.1's "instead of that
       game's own end-of-round screen" is structural: `render()` draws the flow and never calls `game_.render()`.
     - flow active: `flow_.update(in)` first (a `submitted` step calls `store_.record(...)` that same tick, so the
       top-5 screen renders the already-updated table), then `game_.update(...)` with a **neutral, all-false
       `GameInput`** — never skipped. This is load-bearing, not tidiness: `GameSession` tracks `prevStart_` only
       across the ticks it actually sees, so a game frozen with `start` held at the round's end would need *two*
       presses to restart afterwards (R4). On the finishing tick the game gets the **real** input instead, so the
       one `start` rising edge that dismisses the top-5 screen is the very same edge `GameSession` restarts on —
       AC-3.3's "no further intermediate screen", with zero knowledge of galactic-invasion inside the wrapper.
  3. **A5 — ESP-IDF NVS, one blob, behind a `Backend` concept template.** `HighscoreStore<Backend>` (pure, in
     `include/`) owns load/validate/insert/encode/write; `Backend` is `bool read(uint8_t*, int32_t)` +
     `bool write(const uint8_t*, int32_t)`, satisfied on-device by `port::esp32::NvsHighscoreBackend` and on the
     host by a `FakeFlashBackend` over a plain byte array — the exact seam `TilePusher<Transmitter>` and
     `InputReader<Source>` already established (compile-time binding, no vtable, nothing virtual anywhere in this
     codebase). NVS wins because the default partition table this board is already flashed with **has an `nvs`
     partition**, it is wear-levelled and atomic-committing, and it is one `REQUIRES nvs_flash` line; a raw
     partition would mean authoring a `partitions.csv` (a flash-layout change on a live board) plus hand-rolled
     erase-before-write and torn-write recovery. We still write **our own** version + checksum inside the blob:
     NVS's internal CRC proves the bytes are the ones we wrote, never that they match *this* firmware's layout.
  4. **The persisted image is written byte-by-byte, little-endian — never a `memcpy` of a struct.**
     `encodeBlock`/`decodeBlock` over a `uint8_t[kBlockSize]`: magic, `kFormatVersion`, `kGameSlotCount`,
     `kGameSlotCount × kTableSize × (4-byte score + 3 initials)`, FNV-1a checksum. This removes implicit struct
     padding (a checksum over uninitialised padding bytes is non-deterministic), removes the endianness question,
     and makes AC-1.3's "seed corrupt/wrong-version bytes" a plain array poke in a host test.
  5. **A6 — `kGameSlotCount = 5`** (README names five games total: galactic-invasion plus four planned), 175
     bytes of table data. The slot count is **persisted as its own field** and checked against the compile-time
     constant on decode, so growing the table later resets cleanly even if someone forgets the version bump. The
     migration policy is written into `highscore.h`'s doc comment: changing `kGameSlotCount`, `kTableSize`,
     `kInitialsCount` or any field width means bumping `kFormatVersion` in the same commit; no migration code is
     written — a clean reset is the documented answer (constitution §6 permits either).
  6. **A slot is caller-supplied; the system knows no game names (AC-6.1).** `HighscoreGame` takes the slot
     index and the display-name pointer as constructor arguments. Galactic-invasion declares its own identity as
     two namespace-scope `constexpr`s in `galactic_invasion.h` (`kHighscoreSlot = 0`,
     `kHighscoreName[] = "GALACTIC INVASION"`) — data next to the game that owns it, not class surface, and
     therefore outside AC-5.2's "one member" budget by the same reading that already lets that header export its
     layout constants. AC-6.2's two synthetic ids are then a pure host test over two slots.
  7. **An empty slot is `score == 0` — there is no `count` field.** A7 already forbids 0 from ever qualifying, so
     "score > 0" is a total, single-source-of-truth occupancy bit; `count()` counts leading occupied entries.
     Same reasoning as galactic-invasion's zero-size-`Entity`-means-dead (its plan §1 Decision 5), and it keeps
     the persisted layout one field smaller. Decode additionally validates the **semantic** invariant (initials
     in A–Z, scores in `[0, kMaxStoredScore]`, non-increasing, no occupied entry after an empty one) and treats a
     violation exactly like a bad checksum — a clean empty table (NFR-6).
  8. **Layout is derived from font metrics and proven disjoint *by construction*, answering R2 and R3 with one
     mechanism.** Every element on both screens occupies its own glyph row: `rowY(i) = firstRowY + i * rowPitch`
     with distinct, compile-time, strictly increasing row indices. Three general `static_assert`s per screen
     (`rowPitch >= kGlyphHeight`; indices strictly increasing; last row + `kGlyphHeight <= Framebuffer::height()`)
     prove vertical separation for *all* pairs at once — including the top-5 screen's 1-to-5 dynamic rows (R3),
     where N pairwise asserts would silently stop covering a row that gets added later. **R2:** every
     runtime-variable string (the score, up to `kMaxScoreGlyphs = 5` per A14; the display name, up to
     `kMaxNameGlyphs`) is drawn inside a **worst-case field rect** whose width is the maximum glyph count ×
     `kGlyphAdvance`, proven on-screen at compile time; the actual, shorter string is centred *within* that
     already-proven field at runtime (`(maxGlyphs - actual) * kGlyphAdvance / 2`), so a 1-digit and a 5-digit
     score are both provably inside the same rect. Scores are clamped to `kMaxStoredScore` (99999) **on record**,
     so the stored value can never exceed the width the layout proof assumes. Nothing is ever positioned from a
     literal, and per CLAUDE.md the proof is made **twice**: the compile-time invariant above, plus a runtime host
     test that scans each rendered element's actual bounding box and pairwise-intersects them with its own
     independent helper, for 1..5 occupied rows and for 1..5-digit scores.
  9. **Initials entry is a pure state machine (`initials_entry.{h,cpp}`), 100% host-tested.** Letters are held as
     indices into `[0, kLetterCount)` and rendered as `kFirstLetter + index`, so "never a character outside A–Z"
     is structural rather than checked. `up`/`down`/`fire` are rising-edge only (one `bool prev*_` each, AC-2.2's
     no-auto-repeat). **All edge trackers latch `true` at `begin()`** — galactic-invasion's player holds `fire`
     continuously, and a released-state initialisation would auto-confirm letter 1 on the first tick of the screen
     that opens the instant they die (R5). `input.start` is not read at all in this module — AC-2.4 becomes a lint
     rule (`.start` appears nowhere in these two files), not a reviewer's promise. `HighscoreFlow` is the only
     file that reads `start`, and only for the top-5 dismissal.
  10. **The screens are stateless free functions composing `drawText` only** (`drawTitleScreen`'s precedent, and
     the same "no `setPixel`/`fillRect`/`blit`" lint rule): `drawInitialsEntryScreen(fb, score, letters, cursor)`
     and `drawHighscoreTableScreen(fb, displayName, table)`. The active-position indicator is NFR-7/C13's static
     `-` glyph on its own row beneath the active letter only. Neither clears the framebuffer; `HighscoreGame`
     clears, exactly as `GalacticInvasion::render()` already does.

- **Alternatives considered:**
  | Alternative | Why rejected |
  |---|---|
  | `int32_t finalScore()` + `bool outcomeIsWin()` as two accessors | Two members where one POD-returning call does the job, and `won` has no consumer (AC-2.1/C12 forbid outcome text). AC-5.2's "at most one" is met literally by one method, not read generously |
  | `update()` reports back via an out-parameter | Changes the call expression `GameLoop`'s shipped `kGameHasUpdate` concept detects (`game_loop.h`), so it cannot be done without editing a released engine header — forbidden by NFR-4 and out of scope |
  | `GalacticInvasion` owns a `HighscoreFlow` internally | Forces the game to know the storage type (so `GalacticInvasion` becomes a template, breaking every existing `GalacticInvasion game;` and AC-5.3) or forces a vtable this codebase has none of. The wrapper needs neither |
  | A non-template `Store` interface with virtual `read`/`write` | First vtable in the project; `TilePusher`/`InputReader` already answer this question with a compile-time concept |
  | Raw flash partition via `esp_partition` (A5) | Needs a custom `partitions.csv` (flash-layout change on an already-flashed board), plus our own erase-before-write, wear and torn-write handling. NVS ships all of that; boring technology wins |
  | SPIFFS/FATFS/LittleFS | A filesystem — constitution §2's `has-database` note ("flash… no SQL engine, no ORM, no migration files") and NFR-2's allocation ban both point away; also a second partition and a component dependency for one 187-byte record |
  | One NVS key per game slot | Spreads one format version across N keys and makes a partial write a *valid-looking* half-updated table. One blob has exactly one version, one checksum, one commit |
  | `memcpy` the block struct to bytes | Implicit padding is uninitialised → the checksum is not deterministic; also silently assumes little-endian. 30 lines of explicit encoding removes both |
  | Provision exactly 1 game slot now (A6) | US-6 says the API must be reusable *without modification*; a second game would immediately force a format change and wipe galactic-invasion's table for a reason unrelated to it |
  | 8 or 16 slots "for headroom" | Guessing. README names five games; the persisted slot-count field plus the documented bump-and-reset rule make growing later safe and cheap, so headroom buys nothing |
  | A stored `count` field in the table | Two sources of truth for occupancy against A7's already-total "score > 0" rule; the same drift class galactic-invasion rejected a parallel `bool alive` for |
  | N pairwise `!overlaps()` asserts on the top-5 screen (R3) | 15 asserts for 6 elements that must all be kept in sync by hand, and a 6th row added later is silently unproven. The row-pitch invariant proves all pairs at once |
  | Position the score text from a fixed x for its runtime width (R2) | Exactly the bug the Design Review flagged: correct for 5 digits, wrong for 1. Worst-case field + centre-within-field is provable for both |
  | Inverted glyph or blinking active-letter indicator | Settled by the spec itself (C13/R1): `-` underline, no `fillRect` (which the drawText-only lint rule bans anyway), single-frame-verifiable in a static framebuffer dump |
  | Skip `game_.update()` entirely while the flow is on screen | Leaves `GameSession::prevStart_` stale, so the restart press after the top-5 screen silently needs two presses (R4). One neutral-input call per tick costs nothing and keeps the invariant "exactly one update per tick" |
  | Put the highscore modules under `games/` | It is engine, not a game: US-6's whole point is that a second game reuses it. `include/steamcore/` is where the reusable contract belongs |

- **Consequences:** *Easier* — every Must AC is host-provable (`make test`/`test-asan`/`test-gcc`/`lint`/`bench`);
  the wrapper means galactic-invasion gains exactly one method and no state; a second game needs a slot number and
  a name, nothing else; the persisted slot-count field makes A6's "adding slots is a format change" enforced
  rather than remembered. *Harder* — six new engine files plus a `port/` backend is a wide increment (R9); the
  device build gains a new ESP-IDF component (`nvs_flash`, R1); anything including `font.h`/`text.h` is
  auto-enrolled into the existing 8/43 glyph-metric lint rule, which bites late if a bare `8` is written early
  (R6); and a flash write that fails is deliberately invisible at runtime (NFR-9) — the RAM table stays truthful,
  the entry is simply gone after a power cycle.

## 4. Test Strategy

- **Every Must AC except AC-1.5 is host-verifiable, and that is the strategy** (`make test`, `test-asan`,
  `test-gcc`, `lint`, `bench`, `view`). The device-only half is exactly one file
  (`port/esp32/nvs_highscore_backend.cpp`) plus the harness; per constitution §4 it sits outside the host gate by
  construction, so T14 is compile-only insurance and T15 is the one hardware-gated row, anticipated as possibly
  `blocked` (A15).
- **US-1 (persistence)** — T2 is a boundary battery (0, tie, each rank, discard); T3 tests each of six rejection
  paths *individually*, including all-`0xFF` unwritten flash; T4 proves AC-1.2 by reconstructing a store over the
  same bytes, which is the only power-cycle a host can perform; T8 runs the spec's own success signal end to end.
  T12(b)/(c) then mutation-prove the version and slot-count checks, because a missing corruption guard is
  invisible in a passing suite — "no failures" and "nothing looked" are otherwise indistinguishable.
- **US-2 (initials entry)** — 100% pure and host-tested (T5), the same posture `GalacticInvasion` itself takes:
  held-button no-repeat, wrap in both directions, the latched-at-`begin()` edges, `start` inert, and a two-instance
  replay for AC-2.5. AC-2.4 additionally becomes a lint rule (T13d) so "never reads `start`" is structural.
- **US-3 (top-5 screen)** — T6 tests the layout at 1, 2 and 5 occupied rows, proving disjointness twice (a
  compile-time row invariant that covers all pairs at once, and a runtime bounding-box intersection with an
  independent helper), plus AC-3.2's no-placeholder rule; T7 proves the phase transition and T8 the restart edge.
- **US-5 (galactic-invasion)** — T1 lands the one new member and re-runs the released suite unchanged; T8 asserts
  the reported score against the digits the game itself renders on that tick, rather than trusting the accessor
  against the field it returns; T16's `git diff --exit-code` proves no composed engine file moved.
- **Shoulds** — US-4 is covered by T1/T8's byte-identical unwrapped-frame comparisons; US-6 by T4's two-slot
  cross-contamination test and the AC-6.1 source read. Neither is a cut candidate at meaningful cost; if scope
  must shrink, T10 (dumps) and T11 (bench) are the cheapest rows to defer, in that order, since both feed
  `/demo-day` rather than a Must AC.
- **NFR-1** is measured and printed by a bench outside the correctness gate, never asserted as a wall-clock
  `CHECK` (the established posture here). **NFR-2/3/6** are enforced by lint (T13) as well as tested. **NFR-7**'s
  underline is verified as pixels (T6) and looked at as an image (T10).
- **Deliberately not automated, with reasons:** browser `/demo-day` (no browser-observable surface, constitution
  §8); real GCC coverage (`/usr/bin/g++` is Apple clang — `make test-gcc` stays honestly reported as nominal);
  and AC-1.5, which needs a human, a board and a power switch (T15).

## 5. Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| R1 — the device build gains a new ESP-IDF component (`nvs_flash`) and four new `SRCS` entries in a deliberately non-globbing CMake list | Medium: a host-green feature that does not link, or does not boot, on the device | T14's `idf.py build` is the gate; the CMake list fails loudly (undefined reference) by design, and `nvs_flash_init`'s no-free-pages erase-and-retry path is written in from the start, not discovered on the board |
| R2 — the `nvs` partition is missing or full on the board actually in hand | Medium: `init()` fails on a real device only | `init()` returning false is a normal, handled state: `load()` never runs, every table presents empty, nothing crashes (AC-1.3's posture reused). The fake backend's scripted-failure switch tests exactly this path on the host (T4) |
| R3 — first runtime-variable-width text in this codebase (spec R2): a layout proven for a 5-digit score is wrong for a 1-digit one | High: a silently misplaced or overlapping score line that every fixed-width test still passes | Worst-case field rect proven at compile time + centre-within-field at runtime (§1 Decision 8), with T6 testing 1/2/5-digit scores for containment and running an independent runtime intersection over real bounding boxes |
| R4 — `GameSession::prevStart_` goes stale while the game is frozen behind the flow | Medium: the restart after the top-5 screen silently needs two presses, and only if `start` happened to be held at death — easy to miss by hand | The wrapper always calls `game_.update()` once per tick, with neutral input while the flow is up (§1 Decision 2); T8 carries the exact regression test (hold `start` from death through the whole flow, release, one press) |
| R5 — galactic-invasion's player holds `fire` continuously, and the entry screen opens the tick they die | High: letter 1 auto-confirms before the player sees the screen; looks like a random initial, not a bug | All edge trackers latch `true` in `begin()` (§1 Decision 9); T5 tests it directly and T12(d) mutation-proves the test actually catches its removal |
| R6 — anything including `font.h`/`text.h` is auto-enrolled in the existing 8/43 glyph-metric lint rule, and all of `include/`+`src/` is under the 16/240/160 ban | Medium: lint fails late, on a bare `>> 16` in the encoder or a bare `8` in a layout constant — exactly how `kLivesGlyphCount = 8` bit galactic-invasion at T14 | Written into T3's and T6's DoDs up front (byte shifts as `i * kBitsPerByte` in a loop; every layout value derived from `kGlyphAdvance`/`kGlyphHeight`), so the constraint shapes the first draft instead of forcing a rewrite |
| R7 — a checksum over implicit struct padding is non-deterministic, and a `memcpy`'d image silently assumes little-endian | High if missed: intermittent, unreproducible "corrupt" resets on device only | §1 Decision 4: explicit byte-at-a-time little-endian encoding, no struct image ever written; T3 asserts individual byte offsets so a layout drift fails loudly |
| R8 — 12 new test files land in a shared harness holding a fixed 512-case registry (254 used today) | Low: overflow is a hard failure, not a silent drop, but it would land at the very end | Named here so `/increment` watches the case count in `make test`'s summary and records it at T16 |
| R9 — scope: 16 tasks, 10 new engine/port source files, 12 new test files | Medium: review fatigue, or a late row quietly skipped | Strict walking-skeleton-first order (T1 puts a real `GameLoop<HighscoreGame<GalacticInvasion, Store>>` through a full round before any storage or screen exists); every row is one sitting; §4 names the two cheapest rows to defer if scope must shrink |
| R10 — this feature edits a **released** type's public surface (`GalacticInvasion`, v0.3.0-equivalent) | Medium: a regression in a reviewed, shipped feature | The edit is additive only (one method, two constants, one doc-comment amendment); T1 and T8 both re-run the entire pre-existing galactic-invasion suite unchanged (AC-5.3), and T16 audits the resulting public surface line by line |
| R11 — a flash write that fails is deliberately silent (NFR-9), so a player could lose an entry with no feedback | Low, accepted: the alternative is an error screen this console has no vocabulary for | Recorded here and in `highscore.h`'s contract comment; `record()` still returns a bool so a future caller *can* react, and the RAM table stays truthful for the screen the player is looking at |
