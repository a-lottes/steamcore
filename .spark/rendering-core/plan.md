## 1. Architecture Decision

- **Context:** Greenfield. The repo holds `README.md`, `.gitignore` and `.spark/` — no source, no build files, no directory tree. The machine has Apple clang 14.0.3, `/usr/bin/g++`, `make`, `git`, `python3`; **no ESP-IDF, no cmake, no ninja** (constitution §4). Every AC of this spec must be provable today with that toolchain (A2). Constitution §4 makes "no ESP-IDF header in logic code" load-bearing: a module that includes one drops out of the project's only gate. So the layout has to make that structurally impossible, not merely discouraged.

- **Decision:**
  1. **Layout.** Engine code goes to `firmware/steamcore/` — the README/§5 path, chosen so it *becomes* an ESP-IDF component in place: `include/steamcore/*.h` (public headers → future `INCLUDE_DIRS`), `src/*.cpp` (→ future `SRCS`), `test/` (host-only, never in `SRCS`). Adding `firmware/CMakeLists.txt` with `EXTRA_COMPONENT_DIRS` pointing at `firmware/` later turns `steamcore/` and `system/` into components with **no file move**. Hardware-touching code never enters `src/`; it gets its own sibling directory in the driver story.
  2. **Enforcement.** The host `Makefile` compiles `firmware/steamcore/src/*.cpp` **wholesale** with exactly one include path (`firmware/steamcore/include`). No ESP-IDF headers exist on this machine, so an `#include <esp_*.h>` in `src/` is a hard compile error in the gate — the constraint is checked by the compiler on every run. *(Amended 2026-09-01, review F8: an interim version of this build passed three include paths, on the belief that test files needed the extra ones to reach `src/clip.h` and `test/test_harness.h` directly. Review F12 checked that belief against the shipped tree and found it false — no test file includes `clip.h`, and same-directory quoted includes already resolve `test_harness.h` without help. The Makefile was corrected to drop both extra paths; the original wording above, which F8 had flagged as inaccurate, turned out to be the correct target all along.)*
  3. **Build.** One root `Makefile`, GNU-make + clang++, no generator. `make test` is the documented command (AC-1.1): `-std=c++17 -Wall -Wextra -Werror -O2`, prints `N passed, M failed`, exits 0/1. `make test FILTER=<substring>` runs only matching tests (AC-1.4). `make test-asan` rebuilds with `-fsanitize=address,undefined -fno-sanitize-recover=all -O1 -g` (AC-1.3, NFR-3) — `-fno-sanitize-recover=all` is mandatory: plain UBSan prints and still exits 0, which would make the gate silently green. `make test-negative` builds a separate binary with a deliberately failing assertion and asserts a non-zero exit plus test name and `file:line` in the output (AC-1.2). `make test-gcc`, `make bench`, `make lint`, `make test-all` complete the set.
  4. **Test harness.** Hand-rolled, ~120 lines, `firmware/steamcore/test/test_harness.{h,cpp}`: a `STEAMCORE_TEST(name)` macro, a fixed-size `Case` array in a construct-on-first-use function-local static, `CHECK`/`CHECK_EQ` recording `__FILE__`/`__LINE__`, substring filter, pass/fail counters. No allocation, no exceptions, no third-party code.
  5. **Overflow-safe clipping (A11, AC-2.9).** All clip arithmetic is done in `int64_t` and clamped to `[0, kScreenWidth/Height]` before narrowing back to `int32_t`. Every `int32_t` input fits in `int64_t`, so no signed overflow is reachable and UBSan has nothing to find. One shared internal helper in `firmware/steamcore/src/clip.h` (`steamcore::detail`, not public) serves pixel, rect and blit.
  6. **Dirty tracking (US-4).** `DirtyTracker` owns the comparison buffer and initialises it to the sentinel byte `0xFF`, which is not a valid `Color`. First scan therefore reports all 150 tiles dirty (AC-4.8) as a consequence of the ordinary compare rule — no `firstScan` flag, so partial commit right after the first scan (AC-4.7) behaves correctly without a special case. `TileMask` is `uint32_t words_[5]` = exactly 20 bytes (AC-4.6, `static_assert(sizeof(TileMask) == 20)`).
  7. **Naming.** `PascalCase` types, `lowerCamelCase` methods (the only existing style evidence is the README game contract `update()/render()/onCollision()`), `k`-prefixed constants, `trailing_` private members, `snake_case` file names, `steamcore` namespace (§5).
  8. **No global objects in engine code.** This increment creates zero namespace-scope objects. A7's single engine-owned `Framebuffer` has no consumer yet (no game loop, no driver) and NFR-6 makes a consumer-less public symbol a finding — it lands with the engine-bootstrap story, and when it does it must be a construct-on-first-use accessor (`Framebuffer& engineFramebuffer()`), not a namespace-scope global.

- **Alternatives considered:**

  | Alternative | Why rejected |
  |---|---|
  | Minimal cmake now, "so ESP-IDF is closer later" | cmake is **not installed** (§4). AC-1.1 explicitly demands a machine without it. Adding an uninstallable build system is a gate that cannot run. ESP-IDF brings its own cmake later; nothing written now would be reused. |
  | Vendored doctest/Catch2 single header | It is a dependency and must beat "we write those 120 lines ourselves". It doesn't: 7k+ lines nobody on this project will audit, built on `std::string`/`std::vector`/exceptions — which collides head-on with NFR-2's grep gate for `std::vector`/`std::string`, forcing a permanent exception list into every review. Hand-rolled costs one task and stays greppable. Accepted cost: the harness itself must be trusted → T2 makes its failure path an automated check. |
  | Plain `assert()` + one `main()` per file | Cannot satisfy AC-1.1 (pass/fail count), AC-1.2 (`NDEBUG` erases asserts; no test name) or AC-1.4 (no filter). |
  | Engine code at repo root (`src/`) or `firmware/src/` | Violates §5 (layout follows the README) and forces a disruptive move when `firmware/` becomes the ESP-IDF project root with `steamcore/` as a component. |
  | Separate host copy of the sources, or `#ifdef HOST_BUILD` shims | Two truths that drift; the shim variant re-admits ESP-IDF headers into logic files, which is exactly what §4 forbids. One source tree, two compilers. |
  | `firstScan` flag for AC-4.8 instead of the `0xFF` sentinel | A flag needs its own rule for "first scan, then partial commit" (AC-4.7) and is a second state machine to keep consistent. The sentinel makes AC-4.8 fall out of the normal compare. |
  | Clip with `__builtin_add_overflow` / unsigned wraparound | Compiler-specific or subtle; the reviewer cannot check it by reading. `int64_t` intermediates are obviously correct and cost nothing at clip time (once per call, never per pixel). |

- **Consequences:**
  - *Easier:* a gate that runs today on a clean checkout with no installs; a compiler-enforced ESP-IDF-free logic layer; the driver story consumes `TileMask` without touching a file delivered here; the component move to ESP-IDF is additive (one `CMakeLists.txt`, one `idf_component.yml`).
  - *Harder:* the harness is our own code and carries its own bug risk; test discovery is manual (a new `*_test.cpp` is picked up by wildcard, but a test not written is not missed by anyone); `/usr/bin/g++` on macOS **is** clang, so the two-compiler check (NFR-4) is nominal until a real GCC exists — recorded honestly in §4, not claimed as passed.
  - *Known upcoming decision, deliberately not taken here:* the game **registry** mechanism (constitution §3). Naive self-registration via namespace-scope global constructors has undefined init order across translation units and can collide with "no dynamic allocation". Nothing in this plan forecloses any answer: engine code introduces no global objects at all, `Framebuffer`/`Sprite`/`DirtyTracker` are ordinary constructible types with no registration hooks, and the only static-storage object in the repo is the test harness's case list — test-only, and it uses construct-on-first-use precisely as the evidence that this idiom is available when the registry story picks it up.

## 4. Test Strategy

- **Everything in this increment is host unit tests.** There is no integration layer and no device: all 28 ACs of US-1…US-4 are provable with `clang++` alone (A2). One test file per module, one test function per AC (or per AC case group), named after the AC so `make test FILTER=ac_2_9` re-runs a single criterion (AC-1.4) — this is the handle QA uses to record criteria individually per constitution §8.
- **US-1** is tested by the build system testing itself: `make test` (AC-1.1), `make test-negative` as an automated proof that a broken assertion fails loudly with `file:line` (AC-1.2), `make test-asan` (AC-1.3), `make test FILTER=` (AC-1.4). T3's DoD requires temporarily injecting a real out-of-bounds write to confirm the sanitizer target actually fails — an unexercised sanitizer target is an untested one.
- **US-2 / US-3** are pure input→output assertions on framebuffer content. The reference is always read-back of every pixel, not spot checks, so "no other pixel changed" (AC-2.3, AC-3.1) is verified rather than assumed.
- **US-4** is tested through the public scan/commit contract only; the comparison buffer is never inspected directly, so the tests stay valid if the internal representation changes.
- **ASan/UBSan cover** what assertions cannot: out-of-bounds framebuffer and sprite-source access in every off-screen, edge-crossing and extreme-coordinate case (AC-2.7, AC-3.3, NFR-3) and signed overflow in clip arithmetic (AC-2.9). Note that UBSan is only a gate because of `-fno-sanitize-recover=all`; without it, findings print and the process still exits 0.
- **NFR-1** is a separate `-O2` benchmark binary, deliberately not part of `make test` — a timing assertion inside the correctness gate is a flake generator. It runs under `make test-all` and its measurement is recorded with the host it was taken on.
- **NFR-2 / NFR-4** (no allocation, no ESP-IDF header, no resolution literal) are grep-checkable and therefore automated in `make lint` rather than left to reviewer diligence. The ESP-IDF half is additionally enforced by the compiler: `src/` is built with one include path and no ESP-IDF exists on this machine.
- **Deliberately not covered here, and why:**
  - *Device behaviour* — nothing runs on an ESP32; no timing, DMA, SPI or panel claim is made (constitution §4 honest-status rule).
  - *The framebuffer-dump / Python-viewer half of constitution §8* — neither driver nor viewer exists; QA records it as "not capturable yet" per criterion (A3). No image or PGM is produced by these tests.
  - *`/demo-day` in a browser* — there is no browser-observable surface (constitution §8, `no`). Nothing in this increment is visible to a human.
  - *Real GCC* — `/usr/bin/g++` is clang on macOS. `make test-gcc` runs and must pass, but NFR-4's two-compiler claim is honestly reported as unverified until a genuine GCC (or the ESP-IDF xtensa toolchain) is available.

## 5. Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| The hand-rolled harness is itself wrong — a broken test silently passes | Every AC's evidence is worthless; the project's only gate is decorative | T2 makes the failure path an automated check (`make test-negative` proves a broken assertion exits non-zero with name and `file:line`); T3 proves the sanitizer target fails on a real injected fault; harness stays ~120 lines so it can be read in full at review |
| AC-2.9 / AC-3.3 clipping edge cases are genuinely easy to get subtly wrong | Out-of-bounds writes reach the device as memory corruption long after this story | One shared `int64_t` clip helper for pixel, rect and blit — one place to get right instead of three; every clipping AC additionally run under ASan+UBSan (T7, T9) |
| AC-4.7 partial commit is the failed-SPI case and has no consumer yet to catch mistakes | The driver story inherits a contract that looks tested but isn't; a dropped frame becomes a stale tile on the panel | Sentinel-init design makes first scan, re-scan and partial commit one uniform rule (no special cases to desynchronise); T12 tests the partial case explicitly with the exact 10/4/6 split of the AC |
| `/usr/bin/g++` is clang, so NFR-4's two-compiler portability check is nominal | A GCC-only error (or a real ESP-IDF build break) surfaces only on the first firmware build | Recorded honestly in `docs/host-tests.md` and never reported as verified; `CXX` is overridable so a real GCC can be pointed at the suite the moment one exists; C++17 with no compiler extensions keeps the exposure small |
| Registry mechanism (constitution §3) is still open and global-ctor self-registration has undefined cross-TU init order | A bad answer later collides with "no dynamic allocation" and with static init order, and could force a redesign of engine ownership | Explicitly deferred and recorded as an upcoming decision (§1 Consequences); this plan introduces **no** namespace-scope objects in engine code, so nothing is foreclosed; A7's single engine framebuffer is deferred to the bootstrap story and pre-committed to a construct-on-first-use accessor |
| YAGNI risk in reverse: `firmware/steamcore/` is chosen as a future ESP-IDF component root without ESP-IDF present to verify it | The layout turns out wrong at first firmware build and code moves anyway | The claim is small and standard (component = directory with headers, sources and a `CMakeLists.txt`, registered via `EXTRA_COMPONENT_DIRS`); nothing in the host build depends on it being right, so the cost of being wrong is one `git mv`, not a redesign |
| Inherited spec assumption A4 (18-bpp claim irrelevant here) | If wrong, tile *detection* would still be format-independent | No pixel format, scaling or push is in scope; nothing here converts pixels. Re-checked when the panel arrives 2026-09-02 |
